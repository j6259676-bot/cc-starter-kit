The Hope 內部工具

30 分鐘，建立一個認識你的 AI 分身。

不是再開一個聊天視窗，而是一個記得你是誰、你負責什麼、你糾正過它什麼的工作夥伴。 你用得越久，它越像你的同事 —— 前提是你知道怎麼養它。這份起步包就是在教這件事。

三步驟開始 前往 GitHub

Claude Code 與 Codex 都適用。不需要會寫程式，全程用中文對話完成。

你會得到什麼

三件事，一次設定完

這包東西本身只是一組 Markdown 檔案，沒有魔法。真正的價值是它幫你把「AI 該記得什麼」變成看得見、改得動的檔案。

一個認識你的分身

它知道你的名字、角色、負責的事工、說話習慣，還有哪些字你絕對不能被寫錯。每次開新對話都不用重講一遍。

一套會長大的記憶

你糾正過的錯、踩過的坑、正在跑的專案，全部落成檔案。它不會「忘記」，因為它每次開工都會回頭讀。

依角色選配的模組

牧養、設計媒體、資料工具，還有「做大東西」的流程模組。裝你需要的就好，不用全裝。

三步驟開始

從零到能用，大約 30 分鐘

前兩步是安裝，第三步才是重點 —— 你只要說一句話，剩下的它會帶你走。

1

安裝工具

打開 Mac 內建的「終端機」（用 Spotlight 搜尋 Terminal 就有），貼上其中一行：

curl -fsSL https://claude.ai/install.sh | bash

用 Codex 的話改裝 Codex CLI（npm i -g @openai/codex），其餘步驟完全一樣。

裝好後輸入 claude（或 codex）會引導你登入。你需要公司提供的帳號，或自己的訂閱。

2

下載這包東西

不熟 git 也沒關係，直接下載 ZIP，解壓縮到你想放的位置（建議放 ~/Documents/my-agent）：

下載 ZIP

會用 git 的人可以直接 clone，記得 rm -rf .git 斷開跟模板的連結 —— 這個資料夾之後會存你的個人偏好與事工資料，不要推回共用的模板。

3

叫它帶你完成設定

在終端機切到那個資料夾，啟動 AI：

cd ~/Documents/my-agent claude

然後打這五個字，按 Enter：

帶我完成設定

接下來它會訪談你（你是誰、負責什麼、最花時間的三件事、有沒有絕對不能寫錯的字）， 把答案寫進你的設定檔，推薦適合你的模組，最後帶你做一件今天真的要做的事。 全程你只要回答問題，不用自己改任何檔案。

工具相容性

Claude Code 用得了，Codex 也一樣

整包的核心是純文字的規則檔，不綁任何一家工具。差別只在「它開機時會去讀哪個檔名」，而這個差異已經幫你處理好了。

你用的工具它讀的規則檔你要做什麼
Claude CodeCLAUDE.md什麼都不用做
CodexAGENTS.md什麼都不用做 —— 包裡已經附了一份，它會指向 CLAUDE.md

進階：Codex 使用者如果不想多一層指路，在 ~/.codex/config.toml 加一行 project_doc_fallback_filenames = ["CLAUDE.md"]，它就會直接讀 CLAUDE.md。
唯一真正有差的是斜線指令（/brainstorm 那些）：Claude Code 可以自訂，Codex 不行 —— 在 Codex 裡改成直接跟它說「照 commands/plan.md 的規則做」，效果一樣。

最重要的一課

它不是搜尋引擎，是新同事

想像今天來了一位很聰明、但完全不認識你的新同事。你不會期待他第一天就懂你的習慣， 你會在他做錯的時候告訴他。差別只在於：它的「記住」不是靠腦袋，是靠檔案。 檔案裡沒寫的，它下次就忘了。 所以整套系統的關鍵動作只有一個：發現它做錯 → 當場糾正 → 確認它寫進了記憶。

「記下來」

任何它該永遠記住的事，就這樣說：「記下來：以後寫給小組長的訊息，開頭不要用『親愛的』。」
可以追問「你記在哪個檔案？」來確認它真的寫了。

「為什麼你這樣做？」

它的行為讓你意外時，先問原因，不要只是重來。它看得到自己的設定檔，通常能指出哪條規則太模糊，接著說「那幫我改掉」就好。

「要不要建成固定流程？」

同一類事情做到第三次（週報、會議紀錄、社群貼文），就叫它把步驟包成固定流程，以後一句話跑完。

沉默地自己改掉它的產出，是養 AI 分身最浪費的行為 —— 你改了一百次，它還是不知道。 完整說明在 GROWTH.md， 設定完那天請務必讀一次。

上手之後最該學的事

怎麼驗收它，才不會被「應該可以了」騙

新手最貴的失敗長這樣：它說「已經更新好了」，你相信了，兩週後才發現根本沒生效。 這包的設定檔已經要求它「說完成前要有證據」，你要學會的是追問那句話：

你的證據是什麼？

正確的回答長這樣：「我打開了線上網址，看到新的標題。」
不合格的回答長這樣：「我已經更新了，應該可以了。」—— 「應該」兩個字出現就要警覺。

  • 改網頁或工具：打開實際的線上網址看到改動，不是本機檔案、不是編輯器裡跑成功
  • 寄信：寄件備份裡看得到那封信；測試信要寄到外部信箱，寄給自己收不到
  • 寫進表單或資料庫：回頭重讀寫入的那一筆，確認內容跟預期一樣
  • 它卡住的時候：同一件事失敗兩次就該停下來報告，不該一直試第三次、第四次

看模組

為什麼要有「流程」這種東西？

因為新手用 AI 最常見的失敗是：講一句話，它洋洋灑灑做出一大坨東西，你看完覺得「不是我要的」， 但已經分不清哪裡開始歪掉，只好整個重來。原因幾乎都不是 AI 不夠聰明，而是還沒共識就開工。

dev-workflow 把「做」拆成五個關口 —— 拷問、規格、切片、實作、檢查 —— 每一關都要你點頭才往下走。核心一句話：共識前不動工，一片驗收完才做下一片。

什麼時候不要用它：寫一封信、改個錯字、回答一個問題。判準是「你講得完的事情，直接做」。

卡住了？

先問它本人

九成的問題 —— 語氣不對、格式不對、它自作主張、你想加新功能 —— 它自己就能解決。 因為它看得到自己的設定檔，你只要說：

我想要 X，但你剛剛做成 Y，為什麼？我該怎麼調整設定？

真正需要問人的只有兩種：帳號與權限（安裝、登入、公司帳號授權）， 還有「其他人都怎麼用」的經驗交流。
