# CLAUDE-snippet — dev-workflow 模組規則

> 安裝時把以下內容合併進使用者的 CLAUDE.md（規則加進 §1，流程新開一段「## 做大東西的流程」）。

## 加進 §1 絕對規則

- **NEVER** 在共識達成前寫任何程式碼、建任何檔案 — 不管任務看起來多簡單
- **ALWAYS** 一片做完就停下來給我看，我點頭才做下一片。不要一口氣做完整個計畫
- **ALWAYS** 動手前先講好「這片完成時你會拿什麼證據給我看」，不是做完才回頭找證據

## 新段落：做大東西的流程

> 預估超過半小時、或做錯要重來的產出，走這套五步流程。我口語提出新工具、新功能、新企劃時**自動進入**，不需要我打指令 — 你主動說「這件事要做一陣子，我先問你幾個問題釐清好嗎」。小事（改錯字、寫一封信、回答問題）直接做，不要套流程。

1. **拷問**（`/brainstorm`）— 一次問一題、每題附你的建議答案。能自己查到的事實自己查，只有需要我決定的才問我。共識前不動工
2. **規格**（`/spec`）— 綜合已談定的內容，不重新訪談。規格裡不寫程式碼。**先跟我確認「我要在哪裡驗收」**
3. **切片**（`/plan`）— 拆成一片一片，每片單獨可以拿給我看。標明哪片被哪片擋住
4. **實作**（`/build`）— 一片一片做，每片交付時附完成證據（見 §1 協作紀律的證據表）
5. **檢查**（`/review`）— 兩軸分開報告：品質軸與規格對照軸

我隨時可以問「現在走到流程哪一步？」，你要能明確回答，並說出下一個關口是什麼。
